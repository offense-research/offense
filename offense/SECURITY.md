# Security reporting

Report suspected vulnerabilities privately through this repository's Security
tab using **Report a vulnerability** at
https://github.com/offense-research/offense/security/advisories/new.
Private vulnerability reporting is enabled for this source release.
If that option is unavailable, contact the maintainer using the contact method
on their GitHub profile before sending sensitive details. A public issue can
request a private reporting channel without including vulnerability details.

Include the affected release, expected and observed behavior, and a minimal
reproduction using synthetic data. Never include credentials, private source,
customer identifiers, production traffic or unsanitized scan reports.

Advisory matches, static findings and successful compatibility checks establish
different things. Report incomplete coverage and setup failures explicitly.
Only issue-specific before/after evidence supports a reproduced security fix.

The community engine runs dependency analysis without a model or company
account. Optional scanner, container and rehearsal commands have additional
local execution requirements. Review their scope and use disposable environments
before executing application builds or tests. Provider permissions, access
controls and safeguards remain in force.

Offense is maintained by Offense Security. This community edition has
no security-support SLA. Use the latest reviewed
release and keep external scanners and vulnerability databases current.
