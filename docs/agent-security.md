# Security checks embedded in agents

Offense has two ways to fit into an agent host: an available security tool for model-directed investigation, and a deterministic call from the host's lifecycle code. The latter lets the developer run a check before deployment, after deployment or before starting an agent session without inventing a prompt for each run.

The prepared [SDK and integration guide](../sdk/README.md) includes local installation, typed API contracts, Claude Agent SDK and OpenCode examples, an explicit deployment wrapper, and the standalone `offense-automation.mjs` command. Downloads are generated at `/downloads/offense-sdk.tgz` and `/downloads/offense-automation.mjs`. These resources are implemented locally; no npm package has been published and no agent provider is invoked as part of their verification.

The default recommendation is to recheck enrolled repositories on change and daily for newly published advisories. An SDK host must invoke its configured lifecycle events; saving `preDeploy`, `postDeploy` or `agentRun` is not evidence that an external host installed a hook. A pre-deploy or agent-run gate can block known advisory matches at the selected severity. Incomplete provider/coverage evidence remains unknown and blocks by default when a blocking gate is selected. A deliberate `onIncomplete: "report"` override preserves that unknown in the structured result and warning while permitting the host to continue. Post-deploy is reporting only and cannot undo the completed deployment.

The first portable lifecycle capability is metadata-only npm/pnpm dependency audit. It uses the existing public API and read-only MCP capability and does not require a model key. It does not turn advisory matches into confirmed application vulnerabilities, inspect deployed runtime behavior or automatically edit a repository.

The SDK also supplies an explicit authenticated hosted-scan client for the metered tools already supported by the deployment. This is a separate interface from the anonymous dependency audit. A host requests a quote, applies its configured spending ceiling, and submits a job with a stable idempotency key. Source upload, artifact preparation and live target ownership are separate decisions. Customer attribution and metering remain enforced by the existing scanner API; optional local SDK callbacks do not create authenticated billing attribution for anonymous audit requests.

Keep deployment credentials, policy and the code enforcing a gate in the trusted host. A remote MCP connection makes tools available to an LLM; it does not force their use. Claude's [MCP configuration](https://code.claude.com/docs/en/agent-sdk/mcp) and OpenCode's [SDK](https://opencode.ai/docs/sdk/) and [MCP configuration](https://opencode.ai/docs/mcp-servers/) support embedding these tools in hosted applications. Hosts needing per-tool interception can use Claude's documented [hooks](https://code.claude.com/docs/en/agent-sdk/hooks); a hook should match an explicit configured deployment tool rather than guess which arbitrary shell strings deploy an application.

## Scanner dependency review (2026-11-02)

Offense's self-audit distinguishes advisory version matches from installed packages and reachable vulnerable features. No matches below are suppressed in the scanner.

- **Remediated image dependencies:** the API-test image upgrades pip to 26.2 and setuptools to 84.1.0 before installing Schemathesis. The Hermes image uses pnpm 10.34.5, uv 0.13.4, and the upstream frozen dependency update to Pillow 13.0.0. Rebuild existing images to obtain these changes; changing source does not update deployed containers. The public CLI release is separate.
- **Hermes optional dependencies:** the earlier full upstream-lock audit also matched brotlicffi, filelock, msgpack, oauthlib, opentelemetry-api, pyasn1, setuptools and tornado. They were absent from the installed core-only Python environment. They are not cleared for optional use: rescan the resolved environment before enabling extras, development groups or new tools. See [the runtime boundary](dependency-fix-hermes.md#runtime-and-isolation).
- **Semgrep's MCP dependency:** 1.182.1 pins `mcp==1.29.0`. [GHSA-5h93-6whr-6q8j](https://osv.dev/GHSA-5h93-6whr-6q8j) concerns cross-origin HTTP client redirects; [GHSA-rwrf-2pqf-9j8j](https://osv.dev/GHSA-rwrf-2pqf-9j8j) concerns MCP-client tool-schema references; [GHSA-84m7-p3x7-pcfv](https://osv.dev/GHSA-84m7-p3x7-pcfv) and [GHSA-w4fh-qvv9-3v23](https://osv.dev/GHSA-w4fh-qvv9-3v23) concern HTTP servers. Offense invokes only `semgrep scan` with local operator rules, not an MCP client or server. The fixed SDK is 1.30.0, but both Semgrep 1.182.1 and 1.183.0 require 1.29.0. Retain the match pending a compatible upstream release; do not force a conflicting install or expose Semgrep's MCP features. The server audience issue also requires correct authentication configuration, not just a version bump.
- **Semgrep's OpenTelemetry dependency:** [GHSA-xcq7-p3pf-p88h](https://osv.dev/GHSA-xcq7-p3pf-p88h) requires parsing untrusted inbound `tracestate` headers. Offense's bounded offline scan does not accept HTTP requests and sets `OTEL_SDK_DISABLED=true`, metrics off, and version checks off. Semgrep caps this dependency to 1.37.x, below the fixed 1.45.1. Keep this match visible and reassess if adding server instrumentation or changing execution scope.
- **Spectral's minimatch 3.1.5:** [GHSA-g3hv-75wg-m249](https://osv.dev/GHSA-g3hv-75wg-m249) reports an affected range below 11.0.1, but its optimization/preprocessing functions are absent from the inspected 3.1.5 package. Exploitability in this version is not established. Do not force minimatch 11 into consumers requiring the 3.x API solely to silence the range match; seek upstream applicability clarification or a compatible parent upgrade.

These are scoped applicability decisions, not proof that the entire product is vulnerability-free. OS/native image packages, unpinned transitive tool installs, custom Git/URL dependencies and production deployment inventories need separate coverage. An offline adapter's restrictions must also be enforced by its launcher; invoking an engine directly with different commands is outside this assessment.
